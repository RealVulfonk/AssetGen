# PBR texture intake

Маршрут принимает готовые текстуры, переданные пользователем вложением или путём. Для создания новой модели используй [AssetGen](../assetgen/SKILL.md). Правила репозитория обязательны: [AGENTS.md](../../../AGENTS.md). Обычный intake логируется в [журнале работы с ассетами](../../../docs/asset-work-log.md), карточка в `docs/tasks/` для него не создаётся.

## Вход и результат

- Изображение-вложение или путь к файлу — вход пользователя. Для CLI получи доступный локальный путь к вложению, сохрани исходный файл и запиши путь в журнале.
- Штатный split принимает горизонтальный триптих Base Color / Normal / Roughness. Если передана одиночная карта, не разрезай её на три и не выдумывай недостающие PBR-каналы; выясни назначение и недостающие данные, если они необходимы для запрошенного результата.
- `<material_name>` — безопасный snake_case-префикс выходных карт; при отсутствии имени выбери свободное по изображению или контексту.
- `[asset_name]` — необязательное имя **существующей** модели. Если его нет, только проверь, разрежь и сохрани комплект в библиотеку; не выдумывай потребителя.

Перед работой добавь или открой запись в журнале, запиши путь к листу, режим «библиотека» или «подключение к ассету» и критерий проверки. Проверь `git status --short --branch`, сохрани чужие правки и исходный лист.

## 1. Проверь лист до сохранения

Прочитай изображение и убедись:

- три равные вертикальные панели в порядке Base Color, Normal, Roughness;
- детали совпадают по координатам и физическому масштабу;
- Base Color не содержит направленного освещения и теней;
- Normal выглядит как tangent-space OpenGL/Y+, а Roughness — как grayscale data map;
- нет рамок, подписей и разделителей; края визуально проверены на повтор.

Входной лист может нарушать эти требования незаметно. Зафиксируй ограничения; не объявляй бесшовность или математическую корректность доказанными без проверки.

## 2. Разрежь без ресемплирования

```powershell
python tools/split_pbr_sheet.py <лист.png> --out presets/textures --name <имя_материала>
```

Должны появиться `<имя>_base_color.png`, `<имя>_normal.png`, `<имя>_roughness.png`. Проверь размеры и пиксели тестом/сравнением с панелями. Не используй `--force` для чужого комплекта: сначала прочитай существующие файлы и diff; разрешённая замена текущего материала выполняется с `--force` и записью в журнале. Параллельный запуск с тем же именем может отклониться lock-файлом — не удаляй lock, пока другой процесс активен.

Для режима «библиотека» выполни диагностику и обработку стыков следующего раздела, затем дай пути к исходным картам и кандидату; укажи, что к ассету комплект не подключён.

## 3. Диагностика стыков и кандидат

После split для каждого комплекта начни с полосы 24 px: автор предпочёл её результату с 4 px на камне. Значение относится к пикселям, поэтому для маленькой карты выбери полосу, не превышающую половину каждой стороны; при повреждении деталей подбирай ширину по визуальному сравнению. Выполни:

```powershell
New-Item -ItemType Directory -Force out/verification | Out-Null
python tools/process_pbr_seams.py --source presets/textures --out out/verification --name <имя_материала> --band 24
```

Папка `<имя>_seam_candidate` содержит три карты, повторы 2 × 2 до/после и `report.json` с SHA-256, размерами и средней разницей противоположных краёв. Исходный лист и split остаются нетронутыми. При существующей папке команда откажет в перезаписи; для повторного воспроизводимого запуска выбери другую выходную папку. Публикация выполняется целой папкой после успешной обработки; ошибка снимает lock и удаляет временные файлы.

Метод смешивает противоположные края в полосе одной ширины на всех картах без сдвига и ресемплирования. Normal смешивается как вектор и нормализуется в полосе без инверсии Y. Roughness берёт зелёный канал исходника (именно его использует bake) и повторяет его по RGB на всей карте; вне полосы меняются только остальные каналы Roughness. Это приближение, не восстановление высоты или деталей: в частности, доски и гвозди могут размазаться, а направленные детали — не совпасть. Весь комплект всегда `needs_review`, метрика не является доказательством качества. Если обработка невозможна, зафиксируй ошибку и продолжи остальные комплекты.

Осмотри каждый repeat-preview на игровой дистанции и вблизи. Отклони кандидат с нарушением узора; не подменяй им библиотечный split. Только после визуальной проверки можно отдельно подключить кандидат к контрольному ассету, выполнить bake и `verify_outputs`, затем сравнить исходный и исправленный материал в Godot при одинаковых геометрии, UV, камере и холодном, тёплом и скользящем свете. До этих проверок бесшовность не подтверждена.

Отчёт Normal также содержит минимум и максимум длины векторов, число почти нулевых и ненормированных векторов и пикселей с отрицательным Z. Почти нулевой вектор в исходной карте останавливает обработку; прочие отклонения требуют визуальной оценки. Смешивание нормализует только полосу стыка и не исправляет исходную Normal вне неё. Наложение гвоздей и восстановление сложного рисунка не входят в автоматическую обработку: такой кандидат оставь `needs_review` для ручного исправления.

## 4. Подключи к существующему ассету

Открой `specs/models/<asset>.json`, `specs/textures/<asset>.json` и отчёт модели. Выбери конкретный материал-тег; не заменяй `default`, если у модели есть явный тег. Для новой геометрии сначала заверши маршрут AssetGen отдельно.

В выбранном материале задай:

```json
{
  "source_mode": "image",
  "source_detail": {
    "image": "<имя>_base_color.png",
    "tile_size": 2.0,
    "strength": 1.0
  },
  "pbr_detail": {
    "normal": "<имя>_normal.png",
    "roughness": "<имя>_roughness.png",
    "normal_strength": 1.0
  },
  "roughness": 1.0
}
```

Сохрани существующие `preset` и `palette` для обратного переключения. Для неизменённого авторского RGB начни с `brightness: 0`, `contrast: 1`, `ao: 0`, `edge: 0`; в общей спеке `quantize: false`. Физический масштаб бери из листа: 2.0 — значение по умолчанию, а не обязательная величина. При переключении обратно в procedural/mixed удали `pbr_detail`.

```powershell
python assetgen.py validate-texture <ассет>
python assetgen.py model <ассет> --no-copy
python assetgen.py texture <ассет> --no-copy --lighting-preview
python tests/verify_outputs.py <ассет>
```

Повторный `model` удаляет прежний bake — это ожидаемо. Если модель актуальна по `model_digest`, не пересобирай её без необходимости. Проверь отчёт, размеры, бюджет, отсутствие лишних UV и превью со всех сторон.

## 5. Обязательный Godot A/B

Сохранение GLB не завершает приёмку. В изолированной папке `out/verification/<asset>_pbr/` подготовь три варианта с **одинаковыми геометрией, Base Color, UV и скалярными настройками**:

1. `control` — нейтральная Normal и ровная Roughness;
2. `normal_only` — авторская Normal и та же ровная Roughness;
3. `full_pbr` — итоговый материал.

Временные карты и спеки держи вне production. Запусти [verify_pbr_import.gd](../../../tests/verify_pbr_import.gd) через Godot с графическим выводом:

```powershell
& $env:GODOT_BIN --path godot/lighting_preview --script "$PWD/tests/verify_pbr_import.gd" -- <control.glb> <normal_only.glb> <полный.glb> <папка_отчёта>
```

Если `GODOT_BIN` не задан, передай полный путь к console executable Godot 4. Сравни `ab_game.png`, `ab_close.png` и `metrics.json` при холодном, тёплом и скользящем свете. Оба вклада должны быть различимы на игровой дистанции и вблизи; камера и свет между строками не меняются. Для стены можно дополнительно передать импортированный Godot GLB и префаб, но не используй wall-ограничения для других моделей.

## Передача

Запиши в журнал команды, размеры карт, допущения о масштабе, A/B, швы и ограничения. Дай пути к трём исходным PNG, GLB, превью и Godot-отчёту. Не распространяй материал на другие ассеты без отдельного выигрыша при одинаковой камере и свете. Копирование в игровой проект и commit выполняй только по поручению автора.
