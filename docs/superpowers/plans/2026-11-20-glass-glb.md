# Прозрачные материалы AssetGen и экспорт GLB

План выполнен. Проверенные свойства экспортированного стекла и версии инструментов приведены в разделе [«Результат»](#результат). Для новой работы со стеклом заведи [карточку задачи](../../../AGENTS.md) и сошлись на этот план.

**Цель.** Описывать стилизованное стекло в JSON AssetGen и получать рабочий прозрачный материал в Godot из штатного GLB.

**Архитектура.** Существующая геометрия ссылается на тег материала. Опциональное поле материала `opacity` управляет Alpha в финальном Principled BSDF после запекания. Blender передаёт коэффициент через стандартный glTF, а Godot читает его своим импортёром.

**Стек.** AssetGen CLI, JSON Schema, Blender 5.2.3 LTS, GLB 2.0, Godot 4.7.

**Контекст.** [План развития AssetGen](../../assetgen-improvement-plan.md), [текущая спека окна](../../../specs/models/window_01.json), [конвейер MoonProject](../../../../shadows-project/Docs/design/asset_pipeline.md). Соседний репозиторий игры в рабочей папке называется `shadows-project`.

## Контракт

- `opacity` находится в `material_common` текстурной схемы. Тип — число в диапазоне `[0, 1]`, по умолчанию `1`. Поле применимо к любому пресету и пользовательским слоям, независимо от имени тега.
- Прозрачность относится ко всему материалу. Base Color берётся из общего RGB-атласа. Стекло и непрозрачные части имеют разные теги. Для двухсторонней прозрачной поверхности отключаем отсечение обратных граней на материале с `opacity < 1`.
- `model` продолжает собирать геометрию. Финальный материал публикует `texture`. Сохраняем оба варианта экспорта и действующие параметры семплера.
- Первый проход покрывает alpha blending. Физическое преломление, объёмное поглощение, осколки, коллизии окна и обзор ИИ остаются отдельными задачами. Видимая прозрачность GLB сама по себе не задаёт игровую коллизию.

Пример материала для контрольного окна:

```json
"glass": {
  "preset": "flat",
  "palette": "glass_blue",
  "value": 0.6,
  "opacity": 0.35,
  "roughness": 0.24
}
```

## 1. Добавить поле и прозрачность при экспорте

**Файлы.** `schemas/texture.schema.json`, `blender/bake_texture.py`, `tests/test_texture_schema.py`, `tests/verify_texture_pipeline.py`.

- [x] Добавить в существующую проверку схемы случаи `0`, `0.35`, `1` и отсутствие поля для обычного пресета и custom layers. Проверить отказ для `-0.01`, `1.01`, строки и boolean. В Blender-проверке после вызова `finalize_material` проверить `abs(principled.inputs["Alpha"].default_value - 0.35) < 1e-6` и убедиться, что старый материал получает Alpha `1`. Запустить оба теста и увидеть ожидаемое падение.
- [x] Добавить в `material_common.properties` запись `"opacity": {"type": "number", "minimum": 0, "maximum": 1, "default": 1}`. В `resolve_material` добавить `"opacity": 1.0`. В `finalize_material` присвоить `principled.inputs["Alpha"].default_value = config.get("opacity", 1.0)`. При `opacity < 1` задать `material.use_backface_culling = False`. В `build_bake_material` оставить прежний граф Emission и RGB-карту. `material_settings` собирается из разрешённых настроек и должен показать фактическую opacity.
- [x] Запустить `python -m unittest discover -s tests -p "test_*.py" -v` и `& $env:BLENDER -b --factory-startup --python-exit-code 1 -P tests/verify_texture_pipeline.py -- $PWD`. Если `BLENDER` пуст, взять путь из `assetgen.config.json`. Старые проверки цвета и фильтрации должны пройти.

**Файлы.** Новые `specs/models/window_glass_01.json` и `specs/textures/window_glass_01.json`, существующие `tests/verify_outputs.py` и `tests/verify_reference_builds.py`.

- [x] Взять раму из `specs/models/window_01.json` как основу. Контрольное окно имеет ровно два тега `frame` и `glass`. Для стекла использовать одну тонкую вставку. Прозрачные вставки вплотную к каждой стороне исключить, чтобы не дублировать поверхность. Добавить текстурную спеку с примером выше и `size: 128`. Существующие окна служат регрессионными образцами.

Проверить `glass.get("alphaMode") == "BLEND"`, `abs(glass["pbrMetallicRoughness"]["baseColorFactor"][3] - 0.35) < 1e-6`, `glass.get("doubleSided") is True` и `frame.get("alphaMode", "OPAQUE") == "OPAQUE"`. Проверять opacity из соответствующей спеки. Для ключей, которых нет в старых отчётах, сохранить чтение старых ассетов. Добавить окно в набор чистой сборки.

```powershell

python assetgen.py model window_glass_01 --no-copy
python assetgen.py texture window_glass_01 --no-copy --lighting-preview
python tests/verify_outputs.py window_glass_01
python tests/verify_reference_builds.py
```

- [x] Проверить, что экспортёр Blender передал ожидаемую Alpha. Если GLB отличается от контракта, посмотреть узел Alpha в `*_tex.blend` и JSON блока материалов в обоих файлах. Исправить настройку материала перед экспортом и повторить штатную сборку.

Раму проверить на непрозрачность. Штатный двухсветовой PNG приложить к результату, а наличие предмета за стеклом подтвердить отдельным скриншотом, поскольку обычный preview показывает один ассет.

## Результат

- `window_glass_01` собран из двух материалов. Стекло — одна плоскость из двух треугольников, вся модель — 182 треугольника.
- Оба GLB AssetGen и результат `process_asset.py` сохранили `BLEND`, альфу `0.35`, двусторонность стекла, непрозрачность рамы и линейную фильтрацию. Импорт всех трёх файлов подтверждён в Godot 4.7.2 через `tests/verify_glass_import.gd`.
- В `out/interiors/window_glass_01/` лежат `preview_lighting.png`, `preview_through_glass.png` с видом с обеих сторон и под углом, а также проверенный результат обработки в `moonproject_check/`.
- Прошли 14 тестов схем, численные проверки Blender, чистая сборка семи ассетов и проверка двух старых отчётов. При `opacity: 0` Blender экспортирует маску, которая отбрасывает все фрагменты.
