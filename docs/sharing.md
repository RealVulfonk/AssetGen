# Передача проекта через GitHub

## Что получает новый клон

- Исходный код, схемы, шаблоны, модельные и текстурные спеки, палитры и карты из presets/textures.
- Готовые GLB, albedo, превью и переносимые отчёты в library/. Мастерская использует их, когда ещё нет локальной сборки в out/.
- Lockfile браузерных зависимостей, инструкции установки в README и CI для Python-тестов/проверки библиотеки на Windows и Linux.

Blender и node_modules не хранятся в Git. `npm --prefix web ci` восстанавливает ровно пакет из lockfile. Blender нужен для генерации, но не для просмотра библиотеки.

Свой Blender/Godot/output настрой в игнорируемом assetgen.local.json (пример — assetgen.local.example.json). `BLENDER` переопределяет настройку Blender, `ASSETGEN_OUT` — выходную папку. Не меняй общий конфиг ради пути своего компьютера.

## Сохранить работу перед передачей

Заверши задания мастерской, затем:

```powershell
python tools/export_library.py
python tools/check_distribution.py
python -m unittest discover -s tests -p "test_*.py" -v
git status --short
git add specs presets library
# Добавь также намеренные изменения кода/документации.
git commit -m "Save current assets and recipes"
python tools/backup_project.py
```

Экспорт сохраняет последние доступные сборки, не пересобирая их и не меняя художественные параметры. Несобранные JSON остаются в specs; их можно собрать позже. Устаревшая геометрия отмечается мастерской и перестраивается перед новым запеканием.

`out/` содержит локальные .blend и диагностические сборки, `.workbench/` — историю задач и резервные копии. Они не попадут в обычный push. Для полного сохранения команда backup создаёт **вне проекта** папку `<имя-проекта>-backups/<UTC-время>/` с:

- repository.bundle — все Git refs и история; проверяется `git bundle verify`;
- workspace.zip — рабочие исходники (включая незакоммиченное), out/, .workbench/ и другие локальные файлы;
- BACKUP-MANIFEST.json внутри ZIP — перечень архивных файлов с SHA256;
- SHA256SUMS — контрольные суммы ZIP и bundle.

Из архива исключены .git (он сохранён в bundle), node_modules, __pycache__, .venv и venv: зависимости восстанавливаются установкой. Архив проверяется CRC и SHA256 каждого файла перед завершением. Если файл меняется во время чтения, создание архива прерывается: повтори после завершения сборок. Архив не является автоматическим облачным бэкапом — сохрани папку на другом носителе. Полный архив может содержать локальные настройки и рабочую историю; в публичный репозиторий его автоматически не добавляем.

## Восстановить полный локальный снимок

1. Проверь SHA256 файлов по SHA256SUMS.
2. В новой пустой папке выполни `git clone <путь-к-repository.bundle> <папка-восстановления>`.
3. Распакуй workspace.zip **в этот новый клон**, чтобы восстановить незакоммиченные изменения, out/ и историю. Не распаковывай поверх другой активной работы.
4. Установи Python/npm-зависимости по README, настрой Blender при необходимости и запусти мастерскую.

## Опубликовать подготовленную ветку

Удалённый адрес должен указывать на выбранный автором репозиторий GitHub. Публикацию выполняй после просмотра staged/committed изменений:

```powershell
git remote add origin <URL-репозитория-GitHub>
git push -u origin HEAD
```

Команда публикует текущую ветку без переименования и перезаписи чужой истории. Для существующего origin сначала проверь `git remote -v`; не добавляй второй origin. Видимость и доступ участников задаются владельцем в GitHub. Публичная лицензия проекта пока не выбрана; сведения об источниках файлов — в [THIRD_PARTY.md](../THIRD_PARTY.md).
