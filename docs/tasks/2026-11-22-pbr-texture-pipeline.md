# Добавить PBR-конвейер Base Color + Normal + Roughness

Статус — готово. Постановка и промпт оформлены 22 ноября 2026 года; реализация начата в тот же день по поручению автора. 23 ноября завершены splitter, baker, экспорт, стена, полный unittest suite, Godot A/B и регрессии.

## Запрос и приёмка

- Запрос автора — реализовать вариант 2: AssetGen должен принимать согласованные Base Color, Normal и Roughness, запекать их в одном UV-пространстве и экспортировать стандартные PBR-материалы в оба GLB. Дополнительно нужен скрипт разрезания горизонтального триптиха и [промпт для ChatGPT](../prompts/chatgpt-pbr-texture-sheet.md).
- Первый потребитель — плоская `wall_stone_01`, 2 × 0,4 × 2 м, 12 треугольников. Геометрия должна остаться прежней; рельеф появляется только в реакции материала на свет.
- Готово, когда один комплект исходных PNG проходит разрезание, валидацию, bake, экспорт и импорт в Godot; Base Color, Normal и Roughness совпадают по масштабу и расположению деталей; старые спеки без нового поля сохраняют прежний результат.
- Качественная приёмка — A/B в одной Godot-камере при холодном, тёплом и скользящем свете показывает различимый вклад Normal и Roughness на игровой дистанции и вблизи. Если вклад неразличим, не распространять карты на остальные материалы; сохранить измерения и решение автора.

## Исходное состояние и ограничение

Сейчас `source_mode: "image"` запекает только Base Color. `roughness` и `metallic` — скалярные коэффициенты; полей для Normal и текстурной Roughness нет. Текущий `wall_stone_01` и его GLB/превью служат baseline для A/B.

Простое подключение исходной Normal к уже упакованному UV-атласу недопустимо: положения островов и касательные базисы не совпадают с исходным листом. Нужно запечь дополнительные каналы той же проекцией, которой формируется Base Color.

## Предлагаемый минимальный контракт

Использовать общий `source_detail.tile_size` для всех трёх карт, чтобы масштаб нельзя было случайно развести:

```json
"stone": {
  "preset": "stone",
  "palette": "stone_grey_soft",
  "source_mode": "image",
  "source_detail": {
    "image": "wall_stone_base_color.png",
    "tile_size": 2.0,
    "strength": 1.0
  },
  "pbr_detail": {
    "normal": "wall_stone_normal.png",
    "roughness": "wall_stone_roughness.png",
    "normal_strength": 1.0
  },
  "roughness": 1.0
}
```

Семантика первой версии:

- `pbr_detail` допускается только с `source_mode: "image"`; `normal` и `roughness` обязательны внутри объекта, `normal_strength` по умолчанию равен 1.
- Base Color читается как sRGB; Normal и Roughness — как Non-Color. Не применять к данным картам palette, contrast, brightness или quantize.
- Исходная Normal — tangent-space OpenGL/Y+. Согласовать касательный базис исходной проекции с целевой UV; не подменять Normal простым bump из яркости.
- Существующий скаляр `roughness` остаётся множителем glTF. Для неизменённой исходной Roughness задают 1.0. Metallic остаётся скаляром; упаковка не должна незаметно возводить его в квадрат.
- Старые JSON без `pbr_detail` используют прежний один albedo и скалярные коэффициенты без миграции.

Если реализация покажет ограничение этого контракта, сначала добавить датированное решение в карточку и пример, затем изменить схему и документацию.

## Скрипт разрезания листа

Новый `tools/split_pbr_sheet.py` работает в системном Python и разрезает **один горизонтальный лист строго на три равные вертикальные панели** в порядке Base Color, Normal, Roughness.

```powershell
python tools/split_pbr_sheet.py wall_sheet.png --out presets/textures --name wall_stone
```

Ожидаемые файлы без изменения размера и масштаба:

```text
wall_stone_base_color.png
wall_stone_normal.png
wall_stone_roughness.png
```

Требования:

- использовать Pillow и явно добавить совместимую зависимость в `requirements.txt`; текущий стандартный Python-проект её не содержит;
- проверять читаемость изображения, ширину, кратную трём, безопасное snake_case-имя и существование выходной папки;
- не изменять размер и не ресемплировать панели; сохранять RGB-пиксели каждой трети одинакового размера;
- не перезаписывать результаты без явного `--force`; сначала проверить весь вход, затем опубликовать все три файла, чтобы ошибка не оставляла неполный новый комплект;
- печатать три пути и размер панелей; на невалидном входе завершаться ненулевым кодом без новых результатов;
- тесты создают локальные PNG с различимыми RGB-метками: штатный лист, ширина не кратная трём, повреждённый файл, повторный запуск без `--force` и разрешённый overwrite.

Скрипт проверяет геометрию листа, но не может доказать семантическое совпадение трещин или корректность Normal. Это остаётся визуальной и Godot-проверкой.

## План реализации

1. **Зафиксировать baseline.** Сохранить текущие спеки, GLB, размеры, 12 треугольников и Godot-кадры `wall_stone_01`. Подготовить один проверенный триптих и разрезать его скриптом.
2. **Добавить splitter.** Реализовать CLI, Pillow-зависимость и тесты пиксельной идентичности/ошибок. Проверить реальный лист автора без ручного редактирования панелей.
3. **Провести поле через схему.** Изменить `schemas/texture.schema.json`, разрешение настроек и семантическую валидацию имён/файлов. Отдельно проверить неполный `pbr_detail`, неверный `source_mode`, отсутствующий PNG и старую спеку `barrel_01` без нового поля.
4. **Запечь каналы совместно.** В `blender/bake_texture.py` использовать общие координаты и UV для Base Color, Normal и Roughness. Проверить ориентацию Normal на front/side/top и на скользящем свете, UV-поля и mipmaps. Не добавлять геометрический рельеф.
5. **Экспортировать стандартный glTF.** Добавить `<asset>_normal.png` и упакованную `<asset>_orm.png` либо эквивалентный стандартный metallic-roughness результат. Roughness находится в G; каналы, не имеющие входа, нейтральны. Встроить `normalTexture` и `metallicRoughnessTexture` в обычный и `_godot.glb`.
6. **Сохранить атомарность и актуальность.** Включить новые PNG в `report_texture.json`, публикацию, копирование и очистку устаревшего bake после `model`. Не оставлять смесь старых и новых карт при ошибке стадии.
7. **Расширить проверки.** В `tests/verify_outputs.py` проверять наличие и индексы `normalTexture`/`metallicRoughnessTexture`, embedded images, sampler и соответствие новых полей отчёту. Добавить тест нейтральной Normal и известных значений Roughness, повторную сборку и контроль старой спеки.
8. **Проверить Godot.** Импортировать `wall_stone_01_godot.glb`, проверить материал, загрузить существующий префаб и снять A/B без изменения камеры/света. Убедиться, что видимый меш по-прежнему имеет 12 треугольников и одну box-коллизию.
9. **Обновить контракт.** README и AssetGen skill должны содержать формат листа, команду splitter, поля спеки, цветовые пространства, команды сборки и ограничения. В карточку записать фактические кадры, размеры/память карт, команды и итог A/B.

## Решения

- 2026-11-22 — выбран общий `tile_size` из `source_detail`, а не независимый масштаб каждой карты. Основание — требование автора сохранять одинаковые размеры и масштаб. Рассмотрели три отдельных `source_detail`; они допускают рассинхронизацию. Последствие — все каналы используют одну проекцию.
- 2026-11-22 — splitter является отдельным системным Python-инструментом, а не частью Blender bake. Основание — разрезание нужно до валидации спеки и должно работать без Blender. Цена — новая зависимость Pillow; простой стандартный PNG-код не поддержал бы надёжно разные входные форматы.
- 2026-11-22 — первый контракт ограничен режимом `image` и тремя картами автора. Основание — конкретный потребитель `wall_stone_01`. Рассмотрели универсальный PBR DSL с height/metallic/AO и процедурными Normal; это расширяет поддержку без текущего входа. Последствие — procedural/mixed и дополнительные каналы не входят в первую реализацию.
- 2026-11-22 — A/B в игровой камере является обязательной приёмкой, сохраняя ограничение [дорожной карты](../assetgen-roadmap.md). Основание — дополнительные карты оправданы видимым выигрышем, а не количеством каналов. Последствие — успешный экспорт без различимого эффекта не считается основанием массово переводить каталог на PBR.
- 2026-11-23 — для PBR источник получает отдельную UV `AssetGenPBRProjection`, а активной для bake остаётся целевая UV атласа. Проекция выбирает доминантную ось нормали каждой плоской грани и ориентирует tangent/bitangent наружу. Основание — эксперимент с повёрнутой SourceUV подтвердил, что штатный Cycles `NORMAL`/`TANGENT` bake пересчитывает исходный tangent-space в атлас; прямое подключение Normal к атласу неверно. Более простой BOX projection оставлен только для старых материалов. Последствие — на изогнутых и сглаженных поверхностях возможны проекционные швы.
- 2026-11-23 — экспортируется ORM с R=1, G=Roughness, B=1. Roughness подключается через G и умножается на прежний скаляр; Metallic остаётся независимым `metallicFactor`. Основание — стандартный glTF `metallicRoughnessTexture` без изменения смысла существующих полей. Отдельная metallic-карта и процедурные data-карты не добавлялись.
- 2026-11-23 — общая PBR UV сдвинута на `(0.5, 0.5)`, то есть на полтайла. Основание — несоответствующие края авторского источника давали центральный вертикальный шов, уже зарегистрированный как B1 в [карточке пробы](2026-11-22-wall-pbr-chat-prototype.md). Более простое редактирование исходных пикселей отклонено. Последствие — на одиночной стене граница повтора ушла с центра, но исходник не стал бесшовным; размножение тайлов требует отдельной обработки краёв.
- 2026-11-23 — `normal_strength` применяется только экспортированным `normalTexture.scale`, а bake сохраняет несмасштабированную выровненную Normal. Основание — просмотр diff выявил двойное применение силы в source Normal Map и итоговом материале. Численный тест теперь проверяет одинаковый bake при strength 1 и 0,25, а GLB-проверка сверяет scale со спекой. Для `wall_stone_01` со strength 1 пиксели не изменились.

## Сообщённые баги

- **B1 · Центральный вертикальный шов авторского источника.** Первичная запись и исход разовой Godot-пробы находятся в [карточке пробы](2026-11-22-wall-pbr-chat-prototype.md#сообщённые-баги). В production baker воспроизвёлся тот же дефект до полтайлового сдвига. После общего сдвига UV центральная полоса исчезла из `preview_lighting.png` и Godot A/B; пиксели исходных карт не изменялись. Ограничение бесшовности между повторяющимися тайлами сохраняется.

## Результат и проверка

### Реализовано

- В `schemas/texture.schema.json` добавлен `pbr_detail` с обязательными Normal/Roughness и ограничением `source_mode: "image"`; CLI и Workbench проверяют существование всех локальных PNG. Старые спеки без поля не меняют граф источника и экспортируются без новых текстур.
- `blender/bake_texture.py` запекает Base Color, tangent-space Normal и Roughness в общем атласе, создаёт ORM и embedded PBR-материалы в обоих GLB. `blender/common.py` включает tangent accessors только для PBR.
- `assetgen.py`, `workbench.py` и `tools/export_library.py` переносят новые файлы и пути отчётов. Повторный `model` и публикация спеки без PBR удаляют устаревшие Normal/ORM; неуспешная текстурная стадия сохраняет прежний комплект.
- Созданы `tools/split_pbr_sheet.py` и `tests/test_split_pbr_sheet.py`; `requirements.txt` объявляет Pillow. Скрипт проверяет лист, режет RGB-панели без ресемплирования и публикует комплект через временную папку с rollback. Авторский лист 2172 × 724 фактически разрезан штатной командой с `--force` на три панели 724 × 724.
- `wall_stone_01` использует авторские исходники 724 × 724 и bake 512 × 512. Геометрия осталась 2 × 0,4 × 2 м, 12 треугольников; Godot GLB и существующий префаб содержат по одному `StaticBody3D` и одному `CollisionShape3D`.
- Обновлены README, AssetGen skill, библиотека текстур, THIRD_PARTY и [ChatGPT-промпт](../prompts/chatgpt-pbr-texture-sheet.md).

Готовые выходы: [обычный GLB](../../out/exteriors/wall_stone_01/wall_stone_01.glb), [Godot GLB](../../out/exteriors/wall_stone_01/wall_stone_01_godot.glb), [текстурный отчёт](../../out/exteriors/wall_stone_01/report_texture.json), [lighting preview](../../out/exteriors/wall_stone_01/preview_lighting.png). ### Ограничения

- Dominant-axis проекция предназначена прежде всего для плоских low-poly граней. Сглаженные/сильно изогнутые поверхности и масштабирование тайлов по каталогу требуют отдельной визуальной приёмки.
- Splitter проверяет размеры и пиксели, но не семантическое совпадение деталей и не бесшовность. Авторский источник сохраняет ограничение стыка между повторяющимися тайлами.
