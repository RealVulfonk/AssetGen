# Порядок работы агентов в AssetGen

Статус — готово, 2026-11-21.

## Запрос и приёмка

Автор поручил провести ревью документации и задать правила для полуавтономных агентов. Агент должен найти предыдущую работу, завести карточку до изменений, сохранить каждый явно сообщённый баг и объяснить существенный выбор. Другой агент должен суметь продолжить работу по репозиторию. Объём задачи ограничен документацией AssetGen.

## Наблюдения и план

- В корне отсутствует `AGENTS.md`. README ведёт к навыку сборки, очереди ассетов и аудиту. В аудите рядом лежат исходные наблюдения и результаты последующих исправлений. У плана по стеклу есть собственный раздел с результатами.
- Навык предписывает всегда запускать `new` и после трёх сборок обращаться к автору. CLI отклоняет `new` при существующей спеке. Лимит сборок не учитывает причину повторной попытки.
- Ввести одну карточку на задачу, связать точки входа, уточнить порядок проверки и пределы самостоятельных решений. Проверить сценарии новой задачи, продолжения работы и нескольких багов, команды быстрого старта и локальные ссылки.

## Решения

- 2026-11-20 — вести задачу, её баги и основания решений в одном Markdown-файле. Автору и следующему агенту достаточно открыть одну карточку. Отдельный реестр потребовал бы синхронизировать статусы в двух местах. Прежние результаты остаются в аудите и плане по стеклу, поиск по `docs/` охватывает всю историю.
- 2026-11-20 — ограничить работу критерием приёмки и границей между спекой и генератором. Фиксированное число сборок останавливало агента даже при известном исправлении. Теперь следующая попытка требует конкретной правки, а выбор автора нужен при расширении объёма или неразрешённом художественном вопросе.

## Результат и проверка

- Корневой `AGENTS.md` и шаблон в `docs/tasks/` задают порядок работы. Из README и навыка сборки есть переход к правилам. В аудите обозначена дата исходных наблюдений, в выполненном плане по стеклу — переход к результату.
- Разобраны три случая по тексту правил. Для новой задачи первым файлом служит карточка. При продолжении агент находит прежнюю запись и сверяет состояние. Если автор сообщает два дефекта, агент заводит две записи, причём невоспроизведённый дефект сохраняет пометку «сообщён» и собственный следующий шаг.
- Исходная команда `python assetgen.py new barrel barrel_01` воспроизводимо завершилась отказом перезаписать спеку. Обновлённый быстрый старт прошёл в пустом временном `ASSETGEN_OUT`: обе валидации, `model` и `texture` с `--no-copy`, затем `python tests/verify_outputs.py barrel_01 --out <каталог>`. Проверена одна модель и один текстурированный GLB.
- `python -m unittest discover -s tests -p "test_*.py" -v` — прошли 14 тестов. Проверены 37 относительных ссылок в затронутых документах, включая ссылки на разделы.

## Дополнение от 2026-11-21 — ночная обработка папки

Автор уточнил, что хочет передать путь к папке референсов и оставить агента работать до утра. План — описать одну карточку на всю партию, порядок самостоятельного выбора, продолжение после ошибки и проверку результатов после перерыва. Критерий — для каждого входа виден исход, а спорный предмет не задерживает остальные.

Решение — очередь ведёт сам агент в карточке партии. Для сборки достаточно существующего CLI. У предметов независимые спеки и выходные файлы, поэтому агент может отложить один предмет и продолжить остальные. Порядок закреплён в [AGENTS.md](../../AGENTS.md#папка-референсов-на-ночь), пример поручения добавлен в README.

Повторная проверка шести готовых предметов из [предыдущей партии](2026-11-21-examples-reference-models.md) через `python tests/verify_outputs.py wall_lantern_01 pot_clay_01 urn_stone_ornate_01 vase_clay_01 vase_stone_01 door_arch_heavy_01` подтвердила шесть моделей и шесть текстурированных GLB. Та же проверка для одной вазы с пустым каталогом вывода выявила отсутствующий отчёт модели. Новая папка для генерации в этом запросе не указана.
