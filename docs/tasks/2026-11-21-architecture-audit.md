# Аудит AssetGen: развитие моделирования, техдолг и процессы

Статус — готово (22 ноября 2026 года).

## Запрос и приёмка

- Запрос автора — провести аудит проекта; составить план развития возможностей для более сложных и качественных моделей; выполнить ревью кода и архитектуры; собрать задачи техдолга в отдельной папке; предложить для агентной разработки Git-flow, проверки и ограничения роста проекта.
- Границы — анализ и документация текущего рабочего дерева без изменения генератора, спек и имеющихся чужих правок. Существующий план развития учитывается и дополняется, а не пересказывается без проверки.
- Готово, когда есть актуальный план развития с измеримыми критериями, отдельный каталог приоритизированных карточек техдолга с доказательствами и рекомендациями по процессам, а выводы и проверки зафиксированы в этой карточке.

## План

1. Снять карту модулей, схем, CLI, Blender-стадий, экспорта, тестов и вспомогательных инструментов.
2. Проверить архитектурные границы, обработку ошибок, воспроизводимость, дублирование контрактов и реальное покрытие тестами.
3. Сопоставить текущий DSL и качество результатов с очередью ассетов и уже выполненными итерациями.
4. Сформировать план развития, реестр техдолга и процессные изменения с приоритетами, зависимостями и проверяемой приёмкой.
5. Пройти ссылки и команды в новых документах, просмотреть diff и отделить подтверждённые дефекты от гипотез.

## Решения

- 2026-11-21 — результат оформляется как отдельный аудит и каталог `docs/tech-debt/`, существующий `docs/assetgen-improvement-plan.md` сохраняется как исторический и итерационный журнал. Основание — запрос отдельной папки задач и наличие прежнего плана. Рассмотрели перезапись прежнего плана; отклонили, чтобы не смешивать историю с новым реестром. Последствие — новые документы должны явно ссылаться на уже закрытые и открытые направления.
- 2026-11-22 — выбрана эволюция существующих границ без rewrite: общие чистые контракты выносятся только для уже существующих потребителей CLI/Blender/workbench/tools. Основание — рабочие staged builds, schemas, GLB tests и локальные defects вместо системного сбоя архитектуры. Более простой вариант большого рефакторинга отклонён из-за риска потерять уже проверенные контракты. Последствие — сначала TD-001…TD-003, затем точечные общие helpers.
- 2026-11-22 — развитие моделирования начинается с игровых вертикальных срезов и opt-in assemblies; join остаётся default для старых static props. Основание — потребность двери/сундука/обломков и обратная совместимость 124 specs. Универсальный CSG/rig/runtime DSL отложен до конкретного потребителя.

## Результат и проверка

- Изменилось — созданы [центральный аудит](../assetgen-architecture-audit.md), [дорожная карта качества и сложности](../assetgen-roadmap.md), [предлагаемый процесс агентной разработки](../agent-development-process.md) и [реестр техдолга](../tech-debt/README.md) с 14 независимыми карточками TD-001…TD-014. Production-код и спеки этой задачей не менялись; существующие чужие правки сохранены.
- Масштаб актуального дерева — 124 model specs, 112 texture specs, 5999 описанных частей; наибольшая спека `broadleaf_05` содержит 297 частей.
- `python -m unittest discover -s tests -p "test_*.py" -v` — 26/26 прошли.
- `python tools/check_distribution.py` — 124 model specs, 112 texture specs, 48 bundled assets прошли.
- `node --check web/app.js && node --check web/viewer.js` — обе проверки прошли.
- `python tests/verify_reference_builds.py` — 7 моделей/6 textured GLB собраны с нуля; UV, cutouts, lock, failure recovery, stale model guard и rebake invalidation прошли.
- Blender `verify_texture_pipeline.py` — пройден на Blender 5.2.3 LTS; `verify_texture_colors.py` прошёл для найденных PNG, но сохраняет discovery-skips.
- `python tests/verify_outputs.py` — exit 0 при 48 models/42 textured GLB и 76 skipped; зарегистрировано TD-001.
- `python -B tools/gen_flora.py --all --dry-run` — воспроизведён `KeyError: expected_size` на rock; зарегистрировано TD-006.
- Дополнительные fixture/GLB checks — self-intersecting extrude и zero scale приняты схемой; opaque материалы в barrel/window GLB имеют `doubleSided=true`; зарегистрированы TD-013/TD-012.
- Проверка документации — 117 локальных Markdown-ссылок в аудите, roadmap, process, task card и всех TD прошли, отсутствующих целей 0; у всех 14 TD проверены обязательные разделы; `git diff --check` прошёл. Команды сверены с текущим CLI/README, базовый CI и tracked `library/` отражены без устаревших утверждений об их отсутствии/запрете.
- Слабые места проверены отдельно — discovery verification не выдана за полный каталог; старые/default specs и отсутствующие bake учтены в приёмке соответствующих TD. Полная чистая сборка 124 моделей и новый запуск Godot в этом аудите не выполнялись; это явно записано в ограничениях центрального отчёта.
- Осталось — только внедрение предложений отдельными задачами в порядке реестра; найденные дефекты в рамках аудита не исправлялись.
