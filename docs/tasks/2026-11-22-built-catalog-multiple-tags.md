# Каталог собранных моделей и пакетная смена нескольких тегов

Статус — готово.

## Запрос и приёмка

- Скрыть несобранные модели слева; дать выбирать несколько тегов материала и менять их текстуру одной операцией.
- Каталог содержит только модели с GLB. Выбор нескольких моделей и нескольких тегов передаётся одним заданием; каждый ассет запекается один раз с изменениями всех найденных тегов. Отсутствующие теги не создаются, прочие рецепты сохраняются.
- Пользовательские изменения apple_01, bench_01 и bookcase_01 не трогать и не коммитить.

## План

1. Добавить фильтр собранных моделей и отдельный множественный выбор тегов с образцом настроек.
2. Расширить API очереди массивом tags с поддержкой старого tag; проверить разный состав материалов и отсутствие тегов.
3. Проверить UI, тесты, diff и обновить инструкцию.

## Решения

- 2026-11-22 — фильтрация в UI по наличию GLB, без удаления спек. Доступные теги — объединение явных рецептов активной и выбранных моделей. Отдельный список «Образец настроек» определяет отображаемые значения; галочки определяют цели изменения. На все цели переносятся только явно изменённые поля.

## Результат и проверка

- Начальное рабочее дерево проверено; существующие изменения отделены.
- Каталог фильтруется по built, счётчик и категории также считают только собранные модели. Выбранные исчезнувшие GLB снимаются при обновлении. Пустой каталог показывает отдельное состояние и очищает старый 3D-вид.
- Добавлены галочки тегов и отдельный образец настроек; выбор тегов сохраняется при редактировании картинки, режим изменения карты переносится на все выбранные теги. Без тегов кнопка запуска недоступна. Фокус чекбокса сохраняется после обновления списка.
- API принимает tags[], дедуплицирует теги, объединяет изменения в одном candidate на модель, сохраняет список совпавших тегов в истории. Старый tag остаётся совместимым. Ненайденные теги не создаются, модель без совпадений пропускается.
- `python -m unittest discover -s tests -p 'test_*.py' -v` — 24 теста OK. Новый сценарий охватывает 3 модели, 2 найденных тега, дубликат и отсутствующий тег; построены ровно два кандидата, третья модель пропущена, default и специальные параметры сохранены. Некорректные массивы тегов отклоняются до enqueue.
- `python tests/verify_workbench_tags.py` — OK. На изолированной копии barrel_01 реально выполнена очередь с wood+metal, оба материала получили RGB-карту за один item, индивидуальные tile_size сохранились; verify_outputs подтвердил модель и текстурированный GLB. Рабочая спека не изменялась.
- Браузер: 48/48 собранных объектов, строк «Не собрана» нет. Поиск barrel_ показывает две бочки; wood и metal выбираются вместе, совпадения показаны для обеих моделей. Выбор изображения не снимает галочки, снятие всех тегов блокирует запуск. Пробные настройки сброшены, рабочие ассеты из браузера не перезапекались. Консоль без ошибок. Превью — `.workbench/multiple-material-tags.jpg`.
- `node --check web/app.js` и `git diff --check` — успешно. README обновлён.
- Автоматическая проверка отклонила Stop-Process старого сервера (blocked by policy). Обход не выполнялся; обновлённый сервер запущен отдельно на 127.0.0.1:5174 и открыт в браузере. Старая версия на 5173 остаётся запущенной.
- Ограничение: переносятся только отредактированные поля; если выбрать несовместимые процедурные параметры для разных рецептов, валидация отклоняет всю партию до запуска. Обычная замена карты и общих параметров сохраняет индивидуальное устройство рецептов.
