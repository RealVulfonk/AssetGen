# TD-004 · Переносимый контракт report и путей артефактов

Приоритет — P1. Тип — architecture/code. Объём — M.
Статус — предложено. Доказательство — подтверждено кодом и текущими отчётами.

## Проблема и доказательство

CLI переписывает пути в абсолютные в [`assetgen.py:200-208`](../../assetgen.py#L200-L208). Workbench делает собственное remap в [`workbench.py:147-153`](../../workbench.py#L147-L153). Для библиотеки другой преобразователь находится в [`export_library.py:39-45`](../../tools/export_library.py#L39-L45).

[`regroup_out.py:55-60`](../../tools/regroup_out.py#L55-L60) перемещает каталог без изменения отчётов. `verify_outputs.py` использует ожидаемые имена файлов, но не проверяет существование всех путей, объявленных в report.

## Сценарий влияния

После `regroup_out`, копирования backup или переноса output отчёт указывает на прежнюю машину/папку. Файлы рядом могут быть исправны, а потребитель отчёта получает неработоспособные ссылки; три реализации remap могут разойтись при новом поле.

## Границы

Не менять состав стадий и имена файлов. Ввести один способ сериализации путей; схема/версия отчёта добавляется только настолько, насколько нужна для этого контракта.

## Минимальный план

1. Использовать относительные POSIX-пути от корня ассета в опубликованных report; абсолютные пути вычислять только при доступе.
2. Вынести общий serializer/remapper для CLI, workbench и library.
3. Проверять каждый declared artifact и отклонять выход за корень ассета.
4. Определить поведение для legacy absolute report: явная миграция при чтении либо требование пересборки.

## Приёмка

- Один ассет можно перенести в другой output root и пройти verifier без ручной правки JSON.
- `regroup_out --dry-run` ничего не меняет; реальный перенос не оставляет старых путей.
- CLI, workbench и library создают одинаковый path contract.
- Отсутствующий declared GLB/PNG является ошибкой, даже если альтернативный файл с таким именем найден.
