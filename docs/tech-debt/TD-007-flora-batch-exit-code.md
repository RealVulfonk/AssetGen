# TD-007 · Пакетная флора скрывает ошибки и копирует по умолчанию

Приоритет — P1. Тип — code/reliability. Объём — S.
Статус — предложено. Доказательство — подтверждено кодом.

## Проблема и доказательство

[`build_flora.ps1:18-20`](../../tools/build_flora.ps1#L18-L20) вызывает model/texture без `--no-copy`. При настроенном `godot_assets` локальная партия публикуется в игру вопреки общему правилу локальной сборки.

Ошибки только добавляются в список и печатаются в [`build_flora.ps1:14-30`](../../tools/build_flora.ps1#L14-L30); ненулевой `exit` отсутствует. Захваченный `$out` при сбое не выводится, поэтому журнал Blender теряется.

## Сценарий влияния

Несколько ассетов не собрались, но автоматический runner получает код 0. Другой вариант: обычная локальная пакетная проверка изменяет игровой каталог без явного запроса на публикацию.

## Границы

Не менять Pattern, порядок ассетов и продолжение очереди после ошибки. Публикация может остаться только как явный opt-in.

## Минимальный план

1. Добавить `--no-copy` к обеим стадиям по умолчанию; при необходимости ввести named switch для копирования.
2. При любом failed asset печатать журнал этой стадии и завершать скрипт ненулевым кодом после остальных элементов.
3. Добавить изолированный PowerShell-тест с подменённым runner для success/partial failure; не собирать весь лес как unit test.

## Приёмка

- Смешанная партия success+failure продолжает очередь, печатает причину и возвращает ненулевой код.
- При включённом `godot_assets` default-прогон ничего в игру не копирует.
- Полностью успешная партия возвращает 0; отсутствие matched assets имеет явно документированный результат.
- README и usage скрипта описывают opt-in публикацию.
