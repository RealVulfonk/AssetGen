# TD-001 · Strict-режим проверки без скрытых пропусков

Приоритет — P0. Тип — tests/reliability. Объём — M.
Статус — предложено. Доказательство — воспроизведено.

## Проблема и доказательство

[`verify_outputs.py:83-95`](../../tests/verify_outputs.py#L83-L95) пропускает модель без `report.json`, если имена не переданы; [`verify_outputs.py:125-134`](../../tests/verify_outputs.py#L125-L134) аналогично пропускает отсутствующий bake. [`verify_texture_colors.py:54-58`](../../tests/verify_texture_colors.py#L54-L58) пропускает PNG даже для явно переданного имени.

Фактический прогон 22 ноября завершился кодом 0: `Verified 48 models and 42 textured GLBs`, `Skipped 76 specs`. Ранее `verify_texture_colors.py` также успешно завершился, проверив 34 изображения и пропустив 76.

## Сценарий влияния

Новый ассет со сломанной сборкой или незапечённой текстурой отсутствует в `out/`; общая штатная проверка зелёная. CI/агент может принять частичный локальный snapshot за проверку каталога.

## Границы

Сохранить удобный discovery-режим для локального просмотра. Не требовать сборку всех 124 моделей в каждом быстром PR. Добавить strict-режим для явного обязательного набора и полного scheduled-прогона.

## Минимальный план

1. Добавить тесты: отсутствующий обязательный model/texture/PNG даёт ненулевой результат и понятное имя ассета.
2. Ввести `--strict` или manifest обязательных ассетов; для strict любой skip является ошибкой. Явные имена должны вести себя одинаково во всех verifiers.
3. Печатать `selected/passed/skipped/failed`; использовать strict в reference/CI, discovery оставить только явно выбранным режимом.

## Приёмка

- Strict на пустом временном output падает и перечисляет отсутствующие обязательные артефакты.
- Strict на свежем `verify_reference_builds.py` проходит без skip.
- Discovery по-прежнему показывает частичный локальный каталог, но его вывод нельзя принять за strict.
- Неизвестное имя и отсутствующая текстурная пара дают разные понятные ошибки.
