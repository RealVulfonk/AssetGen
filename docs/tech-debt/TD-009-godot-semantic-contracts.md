# TD-009 · Семантический импорт Godot и коллизии

Приоритет — P1. Тип — tests/architecture. Объём — M.
Статус — предложено. Доказательство — подтверждено покрытием тестов.

## Проблема и доказательство

[`verify_outputs.py:102-122`](../../tests/verify_outputs.py#L102-L122) проверяет collision по именам узлов и числу POSITION в GLB. Это не доказывает, что Godot создал ожидаемые CollisionShape и сохранил transform.

Единственный специализированный Godot script [`verify_glass_import.gd`](../../tests/verify_glass_import.gd) проверяет прозрачность/материал окна. Он не входит в `verify_reference_builds.py` и не покрывает общий импорт и collision variants.

## Сценарий влияния

GLB содержит узел с правильным суффиксом, но после фактического импорта коллайдер отсутствует, находится не на месте или имеет неверный тип. Структурный Python-тест при этом зелёный.

## Границы

Не заменять художественный осмотр headless-тестом и не вводить кросс-GPU pixel goldens. Сначала покрыть существующие none/box/mesh/convex, масштаб, pivot и материал; assembly/rig добавляются только вместе с соответствующими этапами дорожной карты.

## Минимальный план

1. Создать временный Godot project и импортировать representative GLB через штатный editor import.
2. Проверять видимые MeshInstance3D, тип и transform collision nodes, габариты/pivot, число и основные свойства материалов.
3. Добавить fixture для каждого collision mode и прозрачного/непрозрачного материала.
4. После стабилизации включить в обязательный CI job TD-003.

## Приёмка

- Для каждого collision mode Godot создаёт ожидаемую игровую структуру, а не только узел с суффиксом в JSON.
- Луч/контрольная точка подтверждает совпадение transform видимой и collision геометрии.
- `none` не создаёт коллизию; стекло сохраняет alpha, рама — непрозрачность.
- Намеренно сдвинутый collision fixture даёт красный результат; изолированный project удаляется после прогона.
