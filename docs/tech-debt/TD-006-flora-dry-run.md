# TD-006 · `gen_flora --all --dry-run` падает на rock

Приоритет — P1. Тип — code/reliability. Объём — S.
Статус — предложено. Доказательство — воспроизведено.

## Проблема и доказательство

`rock` намеренно возвращает `size: None` в [`gen_flora.py:981-988`](../../tools/gen_flora.py#L981-L988), поэтому `build_spec` не создаёт `expected_size` в [`gen_flora.py:1117-1121`](../../tools/gen_flora.py#L1117-L1121). Dry-run безусловно читает отсутствующий ключ в [`gen_flora.py:1201-1204`](../../tools/gen_flora.py#L1201-L1204).

Воспроизведение 22 ноября:

```powershell
python -B tools/gen_flora.py --all --dry-run
```

Команда печатает предыдущие семейства и завершается `KeyError: 'expected_size'` на первом `rock`, код 1. Это ломает документированный read-only сценарий из README.

## Сценарий влияния

Нельзя просмотреть всю партию перед генерацией; агент может перейти к `--force`, хотя требовался только просмотр.

## Границы

Не выдумывать неточный `expected_size` для камней и не менять seed/геометрию. Исправить только представление неизвестного габарита и регрессионный тест.

## Минимальный план

1. Добавить тест dry-run для всех семейств, включая спеку без `expected_size`.
2. Печатать `auto`/`unknown` через `spec.get`; остальные поля не менять.
3. Проверить, что dry-run не создаёт и не перезаписывает JSON.

## Приёмка

- Исходная команда проходит все семейства, печатает итог и возвращает 0.
- У rock видно отсутствие заявленного габарита без traceback.
- Повторный dry-run с тем же seed даёт тот же вывод; содержимое specs не меняется.
