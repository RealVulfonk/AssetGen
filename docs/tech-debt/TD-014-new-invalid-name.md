# TD-014 · `new` оставляет невалидный файл при ошибке имени

Приоритет — P2. Тип — code/reliability. Объём — S.
Статус — предложено. Доказательство — подтверждено кодом.

## Проблема и доказательство

В [`assetgen.py:225-238`](../../assetgen.py#L225-L238) шаблон сначала валидируется со старым именем, затем `data["name"]` заменяется пользовательским, файл записывается и только после этого повторно валидируется.

Для имени, нарушающего `^[a-z0-9_]+$`, команда завершится ошибкой после создания `specs/models/<name>.json`. Проверка существования и последующая запись также не являются одной атомарной операцией при параллельном `new`.

## Сценарий влияния

Агент получает ошибку, исправляет команду и повторяет её, но невалидный файл от первой попытки остаётся в каталоге и попадает в последующие проверки/diff. Два параллельных процесса могут перезаписать результат между exists и write.

## Границы

Не менять шаблоны и правила имён. Не разрешать существующую спеку перезаписывать; атомарность требуется только для создания нового файла.

## Минимальный план

1. Подставить имя и полностью валидировать данные в памяти до записи.
2. Создавать файл эксклюзивно (`x`) либо эквивалентной атомарной операцией.
3. Добавить тесты invalid name, existing destination, успешное создание и отсутствие частичного файла после ошибки.

## Приёмка

- `new barrel BAD-NAME` возвращает ненулевой код и не оставляет файла.
- Повторный `new` на существующее имя не меняет его содержимое.
- Валидный шаблон создаёт спеку, которая сразу проходит `validate`; параллельное создание одного имени имеет одного победителя без перезаписи.
