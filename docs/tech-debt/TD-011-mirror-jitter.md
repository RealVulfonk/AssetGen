# TD-011 · `mirror_x` не сохраняет точную геометрию при jitter

Приоритет — P1. Тип — code/geometry. Объём — S.
Статус — предложено. Доказательство — подтверждено кодом.

## Проблема и доказательство

[`expand()`](../../blender/build_model.py#L147-L159) создаёт отдельную копию с `_mirror`, после чего `main()` вызывает `build_part` для незеркальной и зеркальной части независимо. Каждая получает новые случайные смещения в [`build_model.py:127-130`](../../blender/build_model.py#L127-L130); только затем координаты второй отражаются в [`build_model.py:140-143`](../../blender/build_model.py#L140-L143).

Следовательно, при `jitter > 0` вторая деталь не является точным зеркалом первой. Её построение также дополнительно продвигает общий RNG и влияет на последующие части.

## Сценарий влияния

Симметричные наколенники, стойки или крепления получают разные неровности. Добавление зеркальной детали меняет jitter последующих элементов, хотя автор мог менять только локальную симметрию.

## Границы

Не вводить новый DSL и не запрещать намеренную асимметрию: её можно описать отдельными частями. Для каждого array instance зеркалить именно его геометрию; разные array instances могут иметь собственный jitter.

## Минимальный план

1. Добавить численный тест: каждая вершина mirror равна отражению соответствующей вершины источника при ненулевом jitter.
2. Строить/деформировать источник один раз, затем копировать BMesh и отражать копию с обращением нормалей.
3. Явно проверить влияние на RNG последующих частей и зафиксировать намеренный visual diff контрольного ассета.

## Приёмка

- Mirror с jitter геометрически симметричен, нормали направлены наружу, cutouts и материал совпадают с источником.
- `mirror_x` без jitter и старые спеки без mirror не меняются.
- Array mirror соответствует своему instance, а не предыдущему.
- Два независимых запуска с одним seed совпадают.
